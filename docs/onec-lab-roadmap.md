# Учебный стенд учёта

Продолжение работы по браузерному тренажёру. Стадии 1-4 закрыты в коде стенда. Это по-прежнему не учебная платформа 1С.

## Что уже есть

Тип упражнения `onec-lab`. Движок без DOM: `packages/lesson-engine/src/runtime/onec/`. Золотое `solution` гоняет `pnpm validate`. UI: `apps/web/src/components/onec/OnecStand.tsx`, раннер `OnecLabRunner.tsx`. Свободный режим без зачёта: вкладка «Стенд» на `/sandbox` и страница `/workbench`. Команды стенда пишутся в IndexedDB (`playground:stand`) и общие для обеих страниц. Урок их не трогает. Тема: `topics/onec-workbench/`. Трек `onec` начинается с неё.

Конфигурация зашита в код: контрагенты, номенклатура, склады, поступление (приход), реализация (расход, отказ при нехватке), остатки, пометка удаления, дерево только для чтения, консоль запроса из трёх таблиц. Проведение декларативное. «Записать» и пометка удаления остаток не двигают. Сумма остатка - сумма движений, не себестоимость.

Зачёт `mode`:

- `hybrid` (урок): каждый шаг когда-то стал истинным, и финальные `goal` держатся.
- `steps`: только шаги.
- `snapshot`: только снимок, клики не важны.

Оболочка близкая по схеме (разделы сверху, команды, список, форма, табличная часть, «Провести»), но это не 1С. В хроме нет знака, логотипа и слова «1С:Предприятие». Заголовок окна: «Учебный стенд». Акцент `#c9890a`, шапка `#2c3848`, иконки lucide, шрифт сайта. Текст стенда и сценариев только русский. Строки сайта вокруг (навигация, «Проверить») лежат в `ru.json` и `en.json`.

## Стадии

1. **MVP.** Сделано. Знакомство с окном и первое поступление.
2. **Оператор.** Сделано. Реализация, запрет отрицательного остатка, два склада, перепроведение, пометка удаления не снимает движения.
3. **Разработчик на том же движке.** Сделано в объёме чтения: пустой отчёт при непроведённом документе и дерево конфигурации без редактора.
4. **Запросы.** Сделано узко: одна фраза `ВЫБРАТЬ ... ИЗ ... [ГДЕ ...]` по таблицам Остатки, Поступления, Реализации.
5. **Встроенный язык.** Не начат. Проведение остаётся данными, не скриптом.
6. **Конфигуратор, права, СКД, бухгалтерия.** Не начаты. План счетов сюда не добавлять отдельным флажком.

Снимок базы в синк прогресса не класть. В прогресс пишется сдача упражнения, как у остальных типов. Лимит blob синка сейчас 1 МиБ.

## Куда писать код

Новый тип уже проведён через контракт, раннер, `dispatch`, золото в `validate-topics`, `structural-gates`, `soft-lint`, оба файла скилла `lesson-forge` (после правки `.cursor` гонять `pnpm sync:skills`). Следующий сценарий - YAML в `topics/onec-workbench/` или новая тема, если предмет другой. Поля команд и проверок менять вместе со схемой в `packages/contracts/src/exercise.schema.ts` и спеками. Формы руками не рисовать: список и форма собираются из тех же объектов.

Не тащить стенд в eager-бандл. Роут уже ленивый. Тяжёлый wasm этому движку не нужен.

## Чего не делать

Не встраивать учебную платформу 1С и не публиковать её веб-клиент. Не копировать иконки и логотип. Не обещать в тексте урока язык платформы и СКД. Консоль запроса в стенде - учебный диалект, это сказано в теории `03-queries`.
