# Python’s reference model: assignment, arguments, and object mutation

## In short

A Python variable does not contain a value itself: a name is bound to an object. Assignment normally creates another reference to an existing object rather than a copy. Two names can therefore observe one mutable value, while rebinding one name never changes the other.

## How to answer in an interview

Python works with objects and references to them: assignment, passing an argument, and returning a value pass a reference to an object, not an automatic copy.

- `a = b` binds `a` to the same object as `b`; use `is`, not `==`, to test that identity.
- Mutating a mutable object through one reference is visible through another. This is a common source of side effects with `list`, `dict`, and `set`.
- Reassignment changes only one name binding. An immutable `int`, `str`, or `tuple` yields a new object when it appears to change.
- Arguments use object sharing: a function receives another local name for the same object. It can mutate a passed list, but it cannot rebind the caller’s variable to a new list.

## How it works

Equality and identity answer different questions: `==` compares values, while `is` asks whether there is one object.

```python
first = ["python"]
second = first

second.append("redis")

print(first)
print(first is second)
```

The result is:

```text
['python', 'redis']
True
```

Both names point to one list. Rebinding `second`, however, leaves the original list alone:

```python
first = ["python"]
second = first
second = ["git"]

print(first)
print(second)
```

The same rule explains function arguments:

```python
def add_topic(topics):
    topics.append("pytest")
    topics = ["django"]


plan = ["python"]
add_topic(plan)
print(plan)
```

`append` mutates the shared object, so the result is `['python', 'pytest']`. The final assignment only creates a new local binding named `topics`; it does not affect `plan`.

Closures follow the same model: they retain a cell containing a variable, not a value snapshot. A change through `nonlocal` is therefore visible to every call of that closure.

## Pitfalls

- Do not use `is` to compare strings or numbers: identity there can be an interpreter optimization. Use `==` for values; `is None` is the intentional exception.
- A default such as `items=[]` is created once when the function is defined. Calls without an argument share that list; use `items=None` and make the list in the function body instead.
- When an independent structure is needed, make a copy: `items.copy()` copies only the top level, while `copy.deepcopy()` copies nested objects too.
- `id()` can help debug identity, but it is not a portable memory address. Treating it as one is an implementation detail of CPython, not a Python language guarantee.
