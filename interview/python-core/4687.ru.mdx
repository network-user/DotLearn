# Ссылочная модель Python: что происходит при присваивании, передаче аргумента и изменении объекта

## Суть

В Python переменная не хранит значение «внутри себя»: имя связывается с объектом. Присваивание обычно создаёт новую ссылку на уже существующий объект, а не копию. Поэтому два имени могут видеть одно изменяемое значение, но перепривязка одного имени на другое второе не затрагивает.

## Что ответить на собесе

Python работает с объектами и ссылками на них: присваивание, передача аргумента и возврат значения передают ссылку на объект, а не автоматически копируют данные.

- `a = b` связывает `a` с тем же объектом, что и `b`; это проверяют через `is`, а не через `==`.
- Изменение изменяемого объекта через одну ссылку видно через другую. Для `list`, `dict` и `set` это типичная причина побочных эффектов.
- Переприсваивание имени меняет только его привязку. Неизменяемые `int`, `str`, `tuple` при «изменении» фактически дают новый объект.
- Аргументы передаются по модели *object sharing*: функция получает ещё одно локальное имя для того же объекта. Она может изменить переданный список, но не может перепривязать переменную вызывающего к новому списку.

## Как это работает

Равенство и идентичность отвечают на разные вопросы: `==` сравнивает значения, а `is` — один ли это объект.

```python
first = ["python"]
second = first

second.append("redis")

print(first)
print(first is second)
```

Вывод будет таким:

```text
['python', 'redis']
True
```

Обе переменные указывают на один список. Но если перепривязать `second`, исходный список не изменится:

```python
first = ["python"]
second = first
second = ["git"]

print(first)
print(second)
```

То же правило объясняет передачу в функцию:

```python
def add_topic(topics):
    topics.append("pytest")
    topics = ["django"]


plan = ["python"]
add_topic(plan)
print(plan)
```

`append` меняет общий объект, поэтому результат — `['python', 'pytest']`. Последнее присваивание создаёт только новую локальную привязку `topics` и на `plan` не влияет.

Замыкание следует той же модели: оно хранит ячейку с переменной, а не снимок значения. Поэтому изменение через `nonlocal` увидят все вызовы одной замкнутой функции.

## Подводные камни

- Не используйте `is` для сравнения строк и чисел: совпадение идентичности там может быть следствием оптимизации интерпретатора. Для значений нужен `==`; `is None` — осознанное исключение.
- Значение по умолчанию `items=[]` создаётся один раз при определении функции. Все вызовы без аргумента разделят один список; безопасный вариант — `items=None` и создание списка в теле.
- Если нужна независимая структура, создайте копию: `items.copy()` копирует только верхний уровень, `copy.deepcopy()` — вложенные объекты тоже.
- `id()` годится для отладки идентичности, но его не следует трактовать как переносимый адрес в памяти: это деталь реализации CPython, а не контракт языка.
