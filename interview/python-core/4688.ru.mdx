# Ленивые операторы and и or: короткое замыкание и возвращаемое значение

## Суть

`and` и `or` вычисляют выражения слева направо и останавливаются, как только итог уже известен. Это называется коротким замыканием. Они возвращают не обязательно `True` или `False`, а один из своих операндов — поэтому их используют и для проверок, и для выбора значения.

## Что ответить на собесе

Ленивость `and` и `or` означает, что правая часть не запускается, если левая уже определила результат.

- `left and right` возвращает первый ложный операнд; если все операнды истинны, возвращает последний.
- `left or right` возвращает первый истинный операнд; если все ложны, возвращает последний.
- За счёт этого `user is not None and user.is_active` безопасен: метод не вызовется, когда `user` равен `None`.
- В условиях результат приводится к `bool`, но вне условия важно помнить о возвращаемом объекте, а не только о его истинности.

## Как это работает

У `and` ложный левый операнд уже делает всё выражение ложным, поэтому Python не вычисляет правую часть:

```python
def load_profile():
    print("загрузка")
    return {"name": "Ada"}


cached = None
profile = cached and load_profile()
print(profile)
```

`load_profile` не запустится, а `profile` получит `None`. У `or` обратная логика: если значение уже есть, запасной вариант не нужен.

```python
def read_default():
    print("читаем значение по умолчанию")
    return "guest"


name = "Ada"
display_name = name or read_default()
print(display_name)
```

Здесь `read_default` тоже не вызовется, а `display_name` будет строкой `"Ada"`, не булевым значением.

Ленивость позволяет строить защитные проверки:

```python
user = None
can_edit = user is not None and user.get("role") == "editor"
print(can_edit)
```

Без первой части обращение к `get` у `None` привело бы к `AttributeError`.

## Подводные камни

- `value or fallback` подменит не только `None`, но и любые ложные корректные значения: `0`, `""`, `[]`, `False`. Если заменять надо только `None`, используйте явную проверку.
- Не пишите в правой части важный побочный эффект, если он должен произойти всегда: при коротком замыкании он будет пропущен.
- Цепочка `a and b and c` возвращает операнд, поэтому `result is True` обычно неверная проверка. Если нужен именно флаг, используйте `bool(result)`.
- Это не замена понятной ветке `if`: короткая защитная проверка читается хорошо, а сложная бизнес-логика из `and`/`or` быстро становится неочевидной.
